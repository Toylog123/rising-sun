# 组会汇报材料

这个目录存放每次组会汇报的 PDF（PPT 导出）。

- 文件由网站前端通过 GitHub Contents API 直接上传，无需手动放文件。
- **命名规范：`姓名_汇报内容.pdf`**（由网站按「主讲人 + 议题」自动生成，
  不用手改）。例：`谢俊杰_SEU故障分析与加固优化：DMBF与ZACHO.pdf`
  - 姓名与议题之间的空格会被去掉
  - 议题超过 28 字时优先在「：、，」处断开，结尾若挂在「与 / 和 / 的」上会被去掉
- 仓库里的实际路径前面还带日期 + 随机后缀：
  `YYYY-MM-DD_<随机后缀>_<姓名_汇报内容>.pdf`
  —— 前缀保证唯一不互相覆盖，后半段就是给人看的规范名。
- 每条组会记录在 `website/src/data/meetings.json` 里保存附件的元数据
  （文件名、路径、大小、blob sha、上传时间）。
- 在线预览走 GitHub Pages 直链（本目录位于站点根下），
  下载走 raw 直链。
- 删除组会记录时，网站会顺带删除这里对应的 PDF 文件。
- 上传走 Contents API 的 `PUT /repos/{owner}/{repo}/contents/{path}`，GitHub 会
  自动创建缺失的中间目录，所以不需要手工建目录；只有仓库为空或 PAT 权限
  不对时才会自动改走 Git Data API（自底向上建树）。

本目录下的文件会随 GitHub Pages 一起发布，等同于公开可访问，请勿放置敏感材料。
